# Web Foundation v0.1 Usage Guide

## Status and scope

This guide documents the reviewed v0.1 surface only. The shared packages are:

- `@drakeshard/foundation`;
- `@drakeshard/testing`.

Foundation is browser/runtime infrastructure, not a game engine. Renderer integration, game-domain commands, data decoding, diagnostics UI, RPG systems, tactical systems, and renderer/world-coordinate conversion remain application-owned.

The v0.1 package surface has no root export. Import from explicit subpaths only:

- `@drakeshard/foundation/time`;
- `@drakeshard/foundation/random`;
- `@drakeshard/foundation/input`;
- `@drakeshard/foundation/input/browser`;
- `@drakeshard/foundation/storage`;
- `@drakeshard/foundation/storage/browser`;
- `@drakeshard/testing/clock`.

## Consuming the packages

The repository currently consumes both packages through the pnpm workspace. The packages remain `private: true` until S08-05 chooses the distribution mechanism, so v0.1 does not yet promise public npm installation.

A workspace consumer declares the packages with `workspace:*`:

```json
{
  "dependencies": {
    "@drakeshard/foundation": "workspace:*"
  },
  "devDependencies": {
    "@drakeshard/testing": "workspace:*"
  }
}
```

Do not import package source paths directly. Consumer validation in CI resolves the built public subpaths by package name.

## Fixed-step simulation

The application or renderer owns the frame loop. `FixedStepDriver` receives elapsed frame time and returns how many deterministic simulation ticks to execute plus presentation interpolation data.

```ts
import { FixedStepDriver } from "@drakeshard/foundation/time";

const STEP_MS = 50;
const driver = new FixedStepDriver({
  stepMs: STEP_MS,
  maxFrameDeltaMs: 250,
  maxStepsPerFrame: 5,
});

function onFrame(frameDeltaMs: number): void {
  const frame = driver.advance(frameDeltaMs);

  for (let i = 0; i < frame.steps; i += 1) {
    updateDomainOneTick();
  }

  renderDomain(frame.alpha);

  if (frame.overrun) {
    recordApplicationDiagnostic({
      droppedSteps: frame.droppedSteps,
      clampedMs: frame.clampedMs,
    });
  }
}
```

Foundation does not call `requestAnimationFrame`, read `performance.now()` inside the driver, or own renderer scheduling.

On pause, hidden-tab suspension, or another long interruption, stop feeding simulation time. Before normal progression resumes, reset the application timing baseline and call `driver.reset()`; do not feed the whole background duration into the driver.

Interpolation alpha is presentation-only. It must not mutate authoritative domain state or alter tick results.

## Deterministic RNG

```ts
import {
  DeterministicRng,
  RNG_ALGORITHM_ID,
} from "@drakeshard/foundation/random";

const random = new DeterministicRng(0x00c0ffee);

const first = random.nextUint32();
const normalized = random.nextFloat01();

const savedRandomState = random.snapshot();
const resumed = DeterministicRng.fromState(savedRandomState);

console.log(RNG_ALGORITHM_ID, first, normalized, resumed.nextUint32());
```

The v0.1 algorithm identity is `xoshiro128starstar-v1`. Seed expansion, core transition, and helper draw consumption are compatibility-sensitive. Persist the RNG snapshot in game-owned save data when exact continuation matters; Foundation storage does not do that automatically.

Do not use this RNG for cryptographic or security-sensitive randomness.

## Browser input to deterministic ticks

The input pipeline is:

```text
DOM/browser events
  -> browser adapters
  -> normalized physical records
  -> action binding resolution
  -> input contexts
  -> TickInputHandoff.consumeTick()
  -> game-owned semantic commands/domain update
```

A minimal application-owned setup looks like this:

```ts
import {
  ActionBindingResolver,
  InputContextRouter,
  MonotonicInputSequence,
  type PhysicalInputEvent,
  TickInputHandoff,
} from "@drakeshard/foundation/input";
import {
  BrowserInputLifecycle,
  KeyboardBrowserAdapter,
  PointerBrowserAdapter,
} from "@drakeshard/foundation/input/browser";

const sequence = new MonotonicInputSequence();

const actions = new ActionBindingResolver([
  { action: "game.move-left", binding: { kind: "key", code: "KeyA" } },
  { action: "game.confirm", binding: { kind: "pointer-button", button: 0 } },
]);

const contexts = new InputContextRouter([
  {
    id: "gameplay",
    priority: 0,
    actions: [
      { action: "game.move-left" },
      { action: "game.confirm" },
    ],
  },
]);

contexts.activate("gameplay");

const handoff = new TickInputHandoff({ actions, contexts });
const sink = (event: PhysicalInputEvent): void => handoff.ingest(event);

const lifecycle = new BrowserInputLifecycle({
  focusTarget: window,
  visibilityTarget: document,
  sequence,
  sink,
});

const keyboard = new KeyboardBrowserAdapter({
  keyboardTarget: window,
  lifecycle,
  sequence,
  sink,
});

const canvas = document.querySelector<HTMLCanvasElement>("canvas");
if (!canvas) throw new Error("Missing game canvas");

const pointer = new PointerBrowserAdapter({
  pointerTarget: canvas,
  wheelTarget: canvas,
  lifecycle,
  sequence,
  sink,
});

lifecycle.attach();
keyboard.attach();
pointer.attach();

function updateDomainOneTick(): void {
  const snapshot = handoff.consumeTick();

  // Translate Foundation logical/tick data into the game's authoritative commands.
  // Do not make Foundation InputCommand the domain command model.
  consumeGameInput(snapshot);
}

function destroyInput(): void {
  pointer.detach();
  keyboard.detach();
  lifecycle.detach();
}
```

Logical action/context identifiers are game-owned strings. DOM events, renderer objects, browser timestamps, and world-coordinate objects must not cross into deterministic simulation contracts.

Pointer positions are normalized as viewport CSS pixels. Screen/surface-to-world conversion stays presentation-local. The renderer probe demonstrates this by converting the normalized pointer position outside Foundation before creating a game-domain command.

## Save storage, envelopes, migration, and payload validation

Use browser storage adapters at the application boundary, not from fixed-step simulation code.

```ts
import {
  EnvelopeSaveService,
  type JsonValue,
  SaveMigrationRegistry,
} from "@drakeshard/foundation/storage";
import { IndexedDbSaveStorage } from "@drakeshard/foundation/storage/browser";

const storage = new IndexedDbSaveStorage({
  databaseName: "my-game",
});

const saves = new EnvelopeSaveService<JsonValue>({
  storage,
  gameId: "my-game",
  saveFormatVersion: 2,
  gameVersion: "0.1.0",
  contentVersion: "content-v1",
  migrations: new SaveMigrationRegistry([
    {
      sourceVersion: 1,
      targetVersion: 2,
      migrate(payload) {
        return { ok: true, value: payload };
      },
    },
  ]),
  now: () => new Date().toISOString(),
});

async function saveGame(payload: JsonValue): Promise<void> {
  const result = await saves.save("slot-a", payload);
  if (!result.ok) {
    showSaveFailure(result.error.kind);
  }
}

async function loadGame(): Promise<void> {
  const result = await saves.load("slot-a");

  if (!result.ok) {
    showLoadFailure(result.error.kind);
    return;
  }

  if (result.value === null) return;

  // Foundation validates envelope structure and save-format compatibility.
  // The application still validates game-payload semantics before applying state.
  const decoded = decodeGamePayload(result.value);
  if (!decoded.ok) {
    showLoadFailure("invalid-game-payload");
    return;
  }

  applyLoadedDomainState(decoded.value);
}
```

`saveFormatVersion` controls Foundation's sequential migration path. `gameVersion`, `contentVersion`, and the Foundation package version are separate concepts.

Load-time migration is non-committing: a successful migrated payload is returned in memory and the original stored record is not rewritten automatically. Persisting the current format requires an explicit later save.

Application/domain payload validation remains application-owned. The renderer probe contains a concrete decoder that rejects structurally valid envelopes whose toy-domain positions are outside the valid world.

## Settings

Small synchronous preferences may use `LocalStorageSettingsStorage`. Full saves, replay data, large content, or binary assets must not be placed in the settings path.

```ts
import { LocalStorageSettingsStorage } from "@drakeshard/foundation/storage/browser";

const settings = new LocalStorageSettingsStorage({
  storage: window.localStorage,
  namespace: "my-game:prod",
});

const write = settings.set("audio.master", 0.8);
if (!write.ok) {
  reportSettingsFailure(write.error.kind);
}
```

## Diagnostics ownership

Foundation returns structured information such as:

- fixed-step `clampedMs`, `droppedSteps`, and `overrun`;
- persistence `PersistenceResult` failures;
- deterministic input snapshots and transitions.

The application decides how to aggregate, log, display, sample, or transmit those signals. v0.1 intentionally has no shared diagnostic event bus, overlay, or debug UI.

## Phaser integration pattern

Phaser remains application-local. Feed Phaser's frame delta into Foundation, then project domain state into Phaser objects.

```ts
class GameScene extends Phaser.Scene {
  update(_time: number, frameDeltaMs: number): void {
    const frame = driver.advance(frameDeltaMs);

    for (let i = 0; i < frame.steps; i += 1) {
      updateDomainOneTick();
    }

    syncPhaserPresentation(domainState, frame.alpha);
  }
}
```

The renderer probe follows this pattern in `apps/renderer-probe/src/presentation/phaser-probe.ts`: Phaser owns its scene/game objects and frame callback; Foundation owns only renderer-neutral timing/input/persistence primitives.

## PlayCanvas integration pattern

PlayCanvas also remains application-local. Keep PlayCanvas entities, camera state, ray/screen conversion, and presentation synchronization outside Foundation.

```ts
function onPlayCanvasFrame(frameDeltaMs: number): void {
  const frame = driver.advance(frameDeltaMs);

  for (let i = 0; i < frame.steps; i += 1) {
    updateDomainOneTick();
  }

  syncPlayCanvasEntities(domainState, frame.alpha);
}
```

The renderer probe's `apps/renderer-probe/src/presentation/playcanvas-probe.ts` projects renderer-neutral toy-domain state into PlayCanvas entities and keeps camera/pointer interaction renderer-local. It is evidence for the boundary, not a promised Foundation renderer adapter.

## Testing

`@drakeshard/testing/clock` currently exposes only `ManualClock`.

```ts
import { ManualClock } from "@drakeshard/testing/clock";

const clock = new ManualClock();
clock.advanceBy(16);
```

Use it when tests need explicit, controlled time. The testing package intentionally does not provide a generic simulation framework.

## v0.1 boundaries to preserve

- No renderer types in Foundation or domain contracts.
- No Foundation-owned render loop.
- No game-specific action catalog or authoritative game command model in Foundation input.
- No application payload semantics in Foundation persistence.
- No speculative root, data, debug, renderer, RPG, or Tactical exports.
- No public-registry promise until the dedicated distribution decision is made.
