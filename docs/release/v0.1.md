# Web Foundation v0.1 Release Notes

## Status

Released as Web Foundation `v0.1.0` and handed off for first-production-game adoption.

The `v0.1.0` GitHub Release was published from the validated release-candidate commit with versioned package tarballs for `@drakeshard/foundation` and `@drakeshard/testing` plus `SHA256SUMS`. Post-release installation from the exact versioned GitHub Release asset URLs succeeded. Sprint 08 completed the production-game intake, release-candidate validation, release, readiness review, and Phase 4 handoff.

## Shipped shared packages

The approved shared package set is exactly:

- `@drakeshard/foundation`;
- `@drakeshard/testing`.

The private renderer-probe application is validation evidence and is not a shipped shared package.

## Foundation capabilities

### Deterministic timing

`@drakeshard/foundation/time` provides caller-driven fixed-step timing.

The caller owns the render/browser loop and supplies elapsed frame duration. The driver provides:

- bounded simulation steps per frame;
- frame-delta clamping;
- interpolation alpha;
- dropped-step and overrun diagnostics;
- explicit reset behavior for pause/background resume.

Foundation does not own `requestAnimationFrame` or a renderer loop.

### Deterministic random

`@drakeshard/foundation/random` provides deterministic gameplay RNG using `xoshiro128starstar-v1`.

The public contract includes:

- `nextUint32()`;
- `nextFloat01()`;
- versioned state snapshots;
- exact restoration/continuation.

Golden-vector tests protect seed expansion, output sequence, helper draw consumption, and snapshot continuation.

### Browser input

`@drakeshard/foundation/input` and `@drakeshard/foundation/input/browser` provide:

- normalized keyboard/pointer/wheel records;
- deterministic ingress sequence ordering;
- digital action binding resolution;
- opaque prioritized input contexts;
- tick-consumable action state/transitions/commands;
- browser keyboard/pointer adapters;
- centralized focus/blur/visibility reset coordination.

DOM events, renderer objects, browser timestamps, and renderer/world-coordinate types do not enter deterministic simulation contracts.

### Persistence

`@drakeshard/foundation/storage` and `@drakeshard/foundation/storage/browser` provide:

- JSON-compatible settings storage contracts;
- localStorage-backed small settings;
- serialized save-slot storage contracts;
- IndexedDB-backed save storage;
- `SaveEnvelope`;
- structured persistence failures;
- sequential save migrations;
- non-destructive load-time migration behavior;
- explicit save-format/game/content version metadata boundaries.

Game-payload semantic validation remains application-owned.

### Testing

`@drakeshard/testing/clock` exposes `ManualClock`.

No generic simulation test framework was extracted.

## Browser and renderer assumptions

### Primary CI coverage

Chromium remains the primary full browser suite.

The full Chromium coverage exercises deeper integration paths, including renderer lifecycle, persistence, pointer behavior, deterministic cross-renderer scenarios, and performance regression gates.

### Firefox and WebKit

Firefox and Playwright WebKit run focused compatibility coverage for:

- keyboard input through action/tick handoff;
- IndexedDB save/load across reload;
- lightweight Phaser Canvas startup.

This is targeted compatibility coverage rather than a full three-engine duplication of the Chromium matrix.

### Known browser limitations

- PlayCanvas/WebGL-heavy coverage remains Chromium-only in hosted CI.
- Playwright WebKit on Linux is engine coverage, not native macOS Safari validation.
- Full pointer-cancellation behavior remains primarily Chromium-covered because synthetic capture/cancel behavior differs across Playwright engines.
- Performance observations are Chromium-only and are not portable production targets.

## Renderer integration boundary

Phaser and PlayCanvas are application/presentation technologies, not Foundation dependencies.

The probes verified that:

- authoritative domain state remains plain renderer-neutral TypeScript;
- renderer objects may be destroyed/recreated without becoming authoritative;
- both presentation stacks can reuse the same deterministic/input/persistence boundaries;
- screen/world conversion remains renderer-local.

No generic renderer adapter, Phaser package, PlayCanvas package, or shared renderer lifecycle abstraction is included in v0.1.

## Compatibility records

### Package version

The released package manifests use `0.1.0`.

Package version identifies the shipped API release. It does not determine save compatibility, RNG compatibility, content compatibility, or future network protocol compatibility.

### RNG

Compatibility identity: `xoshiro128starstar-v1`.

Changing deterministic sequence/state semantics requires a new algorithm identifier.

### Saves

`saveFormatVersion` is the only Foundation migration-chain key.

`gameVersion` and `contentVersion` are opaque application-owned metadata. `dataSchemaVersion` is application-owned terminology and has no Foundation runtime type in v0.1.

### Networking

`protocolVersion` is deferred because no networking/wire protocol exists in v0.1.

## Performance record

The current probe regression gates enforce only stable, repeatable signals:

- zero dropped simulation steps in the defined Phaser baseline;
- zero overrun frames in that baseline;
- no simulation frame may exceed the configured five-step cap;
- zero steady PlayCanvas presentation-entity replacement churn in the defined interaction scenario.

Hosted-CI frame-time measurements are recorded as descriptive context only.

No production frame-rate, memory, or device-support guarantee is made by v0.1.

## Runtime dependency record

`@drakeshard/foundation` has one external runtime dependency:

- `idb` 8.0.3, confined to IndexedDB browser storage.

`@drakeshard/testing` has no external runtime dependency.

Phaser, PlayCanvas, Preact, and signals are probe-application dependencies only.

## Non-goals and deferred systems

The following are intentionally outside the v0.1 Foundation surface:

- ECS;
- physics;
- navigation;
- networking/rollback;
- AI framework;
- audio;
- localization;
- shared UI;
- generic renderer adapters;
- generic schema/decoder framework;
- generic diagnostics/event-buffer framework;
- persistence cancellation;
- game-specific combat, progression, jobs/classes, content, quests, economy, objectives, or AI;
- RPG and Tactical shared-domain packages as part of Foundation.

Future shared surfaces require current-consumer evidence and the project admission rule.

## Release and handoff outcome

Web Foundation v0.1.0 is released and the planned pre-v0.1 construction backlog is complete.

- the approved GitHub Release contains the Foundation/testing package tarballs and checksum record;
- clean release-candidate and post-release consumer validation succeeded;
- the first-game readiness review identified no current Foundation infrastructure blocker;
- Phase 4 — First Production Game is now the active Foundation phase;
- future Foundation work must originate from production evidence and continue to satisfy the shared-code admission and compatibility-review rules.

The shared package manifests remain `private: true`; v0.1 distribution uses tagged GitHub Release package tarballs rather than npm/GitHub Packages publication.

## Resolved release blockers

Sprint 07 identified two concrete release blockers, both resolved before this release-note preparation:

- an asynchronous lifecycle/persistence browser-test race, fixed by synchronizing assertions on application-visible completion state;
- the unconsumed `FoundationVersion` public alias, removed from the reviewed public surface.

No unresolved runtime/API blocker was recorded by the Sprint 07 blocker review.
